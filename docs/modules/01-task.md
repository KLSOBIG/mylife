# 任务管理 产品设计文档

> 版本：v1 | 更新：2026-07-23

---

## 1. 模块定义

### 1.1 这是什么

任务是系统的核心载体。所有进入系统的信息，最终都会转化为任务。

### 1.2 解决什么问题

- 信息来源分散，无法统一管理
- 不知道哪些事情需要关注
- 无法追踪事情的处理进度
- 人和 Agent 的协作缺乏统一载体

### 1.3 核心价值

**一切皆任务**。无论是外部事件、用户操作、系统触发，还是插件管理，都以任务形式存在。

---

## 2. 任务类型

| 类型 | 说明 | 示例 |
|------|------|------|
| **事件任务** | 来自外部信息源 | 客户投诉、服务器告警、邮件通知 |
| **操作任务** | 用户主动发起 | 创建规则、修改设置、分配任务 |
| **系统任务** | 系统自动触发 | 定时备份、数据清理、超时升级 |
| **插件任务** | 插件管理相关 | 接入钉钉、配置 Agent、更新插件 |

---

## 3. 注意力级别

每个任务都有一个注意力级别，决定任务如何被处理：

| 级别 | 定义 | 处理方式 | 用户感知 |
|------|------|----------|----------|
| **L0 噪音** | 与你无关 | 自动归档 | 完全无感 |
| **L1 可追踪** | 有信息价值 | AI 追踪 | 有结果时汇报 |
| **L2 需处理** | 需要行动 | Agent 处理 | 完成后汇报 |
| **L3 必须你** | 只有你能做 | 立即通知 | 需要你处理 |

## 4. 任务生命周期

### 4.1 状态定义

| 状态 | 含义 | 典型场景 |
|------|------|----------|
| **待分配** | 新创建，等待分配 | 事件刚进入系统 |
| **已分配** | 已分配给执行器 | 等待 Agent/人开始处理 |
| **进行中** | 正在处理 | Agent 执行中 |
| **待审核** | 执行完成，等待验收 | Agent 提交结果 |
| **已完成** | 验收通过 | 闭环 |
| **已挂起** | 暂停处理 | 等待外部条件 |
| **已升级** | 超时或异常 | 需要更高优先级处理 |
| **已退回** | 审核不通过 | 需要重新处理 |

### 4.2 状态流转

```
        ┌─────────────────────────────────────┐
        │                                     │
创建 → 待分配 → 已分配 → 进行中 → 待审核 → 已完成
  ↓        ↓        ↓        ↓        ↓
  └────────┴────────┴────────┴────────┴→ 挂起/升级/退回
```

### 4.3 自动流转规则

| 场景 | 自动动作 |
|------|----------|
| L3 任务创建 | 自动通知人 |
| L2 任务创建 | 自动分配给 Agent |
| L0 事件进入 | 自动归档 |
| 任务超时（30分钟） | 自动升级 |
| 执行失败 | 自动退回 |

## 5. 任务属性

### 5.1 基础信息

| 属性 | 说明 |
|------|------|
| 标题 | 任务名称，简要描述 |
| 描述 | 详细说明 |
| 类型 | 事件/操作/系统/插件 |
| 优先级 | 紧急/高/中/低 |
| 注意力级别 | L0/L1/L2/L3 |

### 5.2 关联信息

| 属性 | 说明 |
|------|------|
| 来源 | 从哪个信息源来的 |
| 执行者 | 谁在处理（Agent/人） |
| 父任务 | 支持任务拆分 |
| 标签 | 分类标记 |
| 工作空间 | 所属空间 |

### 5.3 时间信息

| 属性 | 说明 |
|------|------|
| 截止时间 | 何时必须完成 |
| 创建时间 | 何时进入系统 |
| 开始时间 | 何时开始处理 |
| 完成时间 | 何时闭环 |

## 6. 任务对话

### 6.1 概念

每个任务都有自己的对话线程，记录人与 AI/Agent 的交互过程。

### 6.2 对话参与者

| 角色 | 说明 |
|------|------|
| 用户（Kael） | 任务的决策者 |
| AI（Nexus） | 任务的协调者 |
| Agent（龙虾等） | 任务的执行者 |

### 6.3 对话场景

**场景一：任务创建**
```
用户：创建一个任务，处理客户投诉
AI：收到，优先级是什么？
用户：紧急
AI：✅ 任务已创建，已通知你处理
```

**场景二：任务执行**
```
AI：已草拟回复稿，请确认
用户：语气太生硬了
AI：已修改，请确认
用户：发送
AI：✅ 已发送，状态更新为"已回复"
```

**场景三：任务跟进**
```
AI：客户尚未回复，需要我自动跟进吗？
用户：好，明天再跟进一次
AI：已设置明天自动跟进
```

## 7. 任务拆分

### 7.1 使用场景

复杂任务需要拆分为多个子任务。

### 7.2 拆分规则

- 父任务状态取决于子任务
- 所有子任务完成后，父任务自动变为待审核
- 子任务可以独立分配给不同执行者

### 7.3 示例

```
父任务：产品发布会准备
├── 子任务1：准备演示材料（分配给 Kael）
├── 子任务2：发送邀请邮件（分配给 龙虾）
└── 子任务3：布置场地（分配给 Kael）
```
