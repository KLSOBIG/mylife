# 规则引擎 产品设计文档

> 版本：v1 | 更新：2026-07-23

---

## 1. 模块定义

### 1.1 这是什么

规则引擎决定事件如何被分发和处理。

### 1.2 解决什么问题

- 所有事件都靠人分拣，效率低
- 重复性的分拣工作应该自动化
- 不同类型的事件需要不同的处理方式
- 需要灵活配置分发策略

### 1.3 核心价值

**规则是对分发的增强。** 通过规则，系统自动决定事件给谁、怎么处理。

## 2. 规则结构

### 2.1 基本格式

```
IF [条件]
THEN [动作]
```

### 2.2 示例

```
IF 关键词包含"紧急"或"故障"
THEN 立即通知人处理
```

---

## 3. 条件系统

### 3.1 条件类型

| 类型 | 说明 | 示例 |
|------|------|------|
| 来源 | 事件从哪来 | 来自钉钉、邮件、RSS |
| 关键词 | 内容包含什么 | 包含"紧急""故障" |
| 发送人 | 谁发的 | 来自老板 |
| 时间 | 什么时候 | 工作时间外 |
| 标签 | 什么类型 | 标记为"代码" |
| 内容 | 具体内容 | 包含"@Kael" |

### 3.2 条件组合

支持 AND、OR、NOT 逻辑：

```
IF 来源 == 邮件 AND (关键词包含"紧急" OR 发送人 == 老板)
THEN 立即通知
```

---

## 4. 动作系统

### 4.1 动作类型

| 动作 | 说明 |
|------|------|
| 设置级别 | 设置 L0/L1/L2/L3 |
| 分配执行器 | 给龙虾、给 Harness、给人 |
| 添加标签 | 打标签分类 |
| 发送通知 | 通知到指定渠道 |
| 归档 | 自动归档 |
| 触发工作流 | 执行预设流程 |

### 4.2 动作组合

一个规则可以有多个动作：

```
IF 关键词包含"故障"
THEN
  1. 设置级别为 L3
  2. 分配给 Kael
  3. 发送钉钉通知
```

## 6. AI 建议规则

### 6.1 概念

系统分析用户行为，自动推荐规则。

### 6.2 建议示例

```
AI 建议：
┌─────────────────────────────────────────────────┐
│ 📧 周报提醒自动归档                              │
│ 你总是周五才处理周报，建议其他时间自动归档         │
│ 置信度: 85%                                     │
│ [添加] [忽略]                                   │
├─────────────────────────────────────────────────┤
│ 💬 产品群消息自动摘要                             │
│ 产品群消息较多，建议AI自动摘要后再推送             │
│ 置信度: 90%                                     │
│ [添加] [忽略]                                   │
└─────────────────────────────────────────────────┘
```

### 6.3 学习机制

| 用户行为 | AI 学到的 |
|----------|----------|
| 总是周五处理周报 | 周报提醒 → 自动归档（非周五） |
| 产品群消息从不回复 | 产品群消息 → 自动摘要 |
| 总是收藏 AI 资讯 | AI 资讯 → 有价值，继续追踪 |

## 7. 规则创建

### 7.1 通过对话创建

```
用户：当收到紧急消息时，立即通知我
AI 解析：
  条件：关键词包含"紧急""故障""告警"
  动作：L3 → 立即通知人
AI：✅ 规则已创建
```

### 7.2 通过界面创建

点击"+ 通过对话创建规则"，输入自然语言描述，AI 自动解析并创建。

---

## 8. 规则管理

### 8.1 启用/禁用

每个规则可以独立启用或禁用。

### 8.2 优先级

规则按优先级排序，高优先级规则先匹配。

### 8.3 统计

- 触发次数
- 最后触发时间
- 成功率

## 9. 与其他模块的关系

| 模块 | 关系 |
|------|------|
| 任务管理 | 规则决定任务如何分发 |

| 对话引擎 | 通过对话创建规则 |
