# 执行器 产品设计文档

> 版本：v1 | 更新：2026-07-23

---

## 1. 模块定义

### 1.1 这是什么

执行器是实际干活的实体。系统只负责分发，执行器负责执行。

### 1.2 解决什么问题

- 人精力有限，无法处理所有事情
- 重复性工作需要自动化
- 不同类型的任务需要不同的处理能力
- 需要统一管理所有"干活的"

### 1.3 核心价值

**人只做决策，执行器做执行。** 系统把合适的任务分发给合适的执行器。

---

## 2. 执行器类型

### 2.1 Agent 执行器

AI 系统，可以独立执行任务。

| 名称 | 类型 | 能力 |
|------|------|------|
| 龙虾 | 信息 Agent | 信息检索、内容摘要、报告生成、资讯追踪 |
| Harness | 代码 Agent | 代码生成、代码审查、Bug 修复、重构 |
| Codex | 架构 Agent | 代码生成、架构设计、技术方案 |

### 2.2 人执行器

人类用户，处理需要决策的任务。

| 名称 | 角色 | 能力 |
|------|------|------|
| Kael | 管理员 | 决策审批、任务分配、规则配置、创意工作 |

---

## 3. 执行器状态

| 状态 | 含义 | 可接受任务 |
|------|------|------------|
| **空闲** | 等待任务 | ✅ |
| **忙碌** | 正在执行 | ❌ |
| **离线** | 不可用 | ❌ |
| **错误** | 执行出错 | ❌ |

---

## 4. 执行流程

### 4.1 标准流程

```
接收任务
    ↓
检查能力匹配
    ↓
执行任务
    ↓
提交结果
    ↓
等待验收
```

### 4.2 异常处理

| 异常 | 处理方式 |
|------|----------|
| 能力不匹配 | 拒绝任务，通知协调器 |
| 执行超时 | 自动升级，通知人 |
| 执行失败 | 记录错误，通知人 |
| 执行器离线 | 任务重新分配 |

---

## 5. 执行器能力

### 5.1 能力声明

每个执行器声明自己的能力，系统根据能力匹配任务。

### 5.2 能力示例

**龙虾（信息 Agent）**
- 信息检索：从各种来源检索信息
- 内容摘要：生成内容摘要
- 报告生成：生成分析报告
- 资讯追踪：持续追踪特定话题

**Harness（代码 Agent）**
- 代码生成：根据需求生成代码
- 代码审查：审查代码质量
- Bug 修复：定位和修复 Bug
- 重构：优化代码结构

**Kael（人）**
- 决策审批：最终决策
- 任务分配：分配任务给 Agent
- 规则配置：配置系统规则
- 创意工作：需要创造力的工作

## 6. 协调器

### 6.1 这是什么

协调器负责监督所有执行器，确保任务正确执行。

### 6.2 职责

| 职责 | 说明 |
|------|------|
| 状态监控 | 监控执行器健康状态 |
| 超时处理 | 执行超时时自动升级 |
| 失败处理 | 执行失败时通知人 |
| 质量验收 | 关键操作二次确认 |

### 6.3 监控指标

| 指标 | 说明 |
|------|------|
| 活跃执行器数 | 当前可用的执行器数量 |
| 执行中任务数 | 正在执行的任务数量 |
| 今日完成数 | 今天完成的任务数量 |
| 成功率 | 执行成功的比例 |

---

## 7. 执行器管理

### 7.1 添加执行器

通过对话添加：
```
用户：添加一个新的代码 Agent
AI：请描述这个 Agent 的能力
用户：可以执行 Python 脚本
AI：✅ Agent 已添加
```

### 7.2 配置执行器

- 设置最大并发任务数
- 设置执行超时时间
- 配置能力列表

### 7.3 停用执行器

临时停用，不接受新任务，正在执行的任务继续完成。
