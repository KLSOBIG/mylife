# 插件系统 产品设计文档

> 版本：v2 | 更新：2026-07-24

---

## 1. 模块定义

### 1.1 这是什么

插件系统是系统的扩展机制，通过标准接口接入各种能力。

### 1.2 解决什么问题

- 需要对接各种外部系统（钉钉、飞书、邮件等）
- 需要接入各种执行器（龙虾、Harness、Codex 等）
- 不同系统的接入方式不同（API、CLI、Webhook 等）
- 需要统一的扩展机制

### 1.3 核心价值

**标准化接入，即插即用。** 所有外部能力通过统一接口接入，系统只负责驱动。

## 2. 插件类型

| 类型 | 说明 | 示例 |
|------|------|------|
| **信息源** | 接收外部事件 | 钉钉、邮件、RSS |
| **执行器** | 处理任务 | 龙虾、Harness、Codex |
| **规则** | 定义分发策略 | 关键词规则、时间规则 |

---

## 3. 接入方式

| 方式 | 说明 | 适用场景 |
|------|------|----------|
| **API** | 调用远程接口 | GPT-4、在线服务 |
| **CLI** | 调用本地命令 | OpenCode、本地工具 |
| **SDK** | 直接调用代码库 | Go 库、Python 库 |
| **Webhook** | 接收推送 | 钉钉、飞书消息 |
| **轮询** | 定时拉取 | RSS、定时任务 |
| **流式** | 长连接 | 实时消息 |

---

## 4. 信息源插件

### 4.1 职责

接收外部信息，转换为系统事件。

### 4.2 接入流程

```
外部系统 → 信息源插件 → 系统事件 → 任务
```

### 4.3 预设信息源

| 名称 | 接入方式 | 说明 |
|------|----------|------|
| 钉钉 | Webhook | 接收钉钉群消息 |
| 邮件 | API | 接收邮件 |
| RSS | 轮询 | 定时拉取资讯 |

### 4.4 扩展信息源

| 名称 | 接入方式 | 说明 |
|------|----------|------|
| 飞书 | Webhook | 接收飞书消息 |
| 企微 | Webhook | 接收企业微信消息 |
| 爬虫 | 轮询 | 定时抓取网页 |

---

## 5. 执行器插件

### 5.1 职责

接收任务，执行并返回结果。

### 5.2 接入流程

```
任务 → 执行器插件 → 执行 → 结果
```

### 5.3 预设执行器

| 名称 | 接入方式 | 说明 |
|------|----------|------|
| 龙虾 | SDK | 信息处理 |
| Harness | CLI | 代码处理 |
| Codex | CLI | 架构设计 |
| OpenCode | CLI | 通用代码执行 |

### 5.4 扩展执行器

| 名称 | 接入方式 | 说明 |
|------|----------|------|
| GPT-4 | API | 大语言模型 |
| Claude | API | 大语言模型 |
| 自定义脚本 | CLI | 用户自定义 |

## 7. 插件管理

### 7.1 添加插件

通过对话添加：
```
用户：接入飞书机器人
AI：请提供飞书应用的 App ID 和 App Secret
用户：xxx
AI：✅ 飞书已接入，开始接收消息
```

### 7.2 启用/禁用

每个插件可以独立启用或禁用。

### 7.3 健康检查

系统定期检查插件状态，异常时通知。

### 7.4 配置管理

每个插件有自己的配置项，通过界面或对话配置。

## 9. AI 生成插件

### 9.1 概念

AI 可以根据用户描述，自动生成插件代码。

### 9.2 流程

```
用户：接入飞书机器人
AI：分析需求...
AI：生成插件代码...
AI：✅ 插件已生成，请配置 App ID 和 Secret
```

### 9.3 模板系统

系统提供插件模板，AI 基于模板生成：
- 信息源模板（API/Webhook/轮询）
- 执行器模板（API/CLI/SDK）
- 规则模板

## 11. 当前实现状态（2026-07-24）

### 11.1 已实现

- 本地插件注册表：`data/plugins.json`
- 本地规则注册表：`data/rules.json`
- 本地插件运行时：`server/app.mjs` + `server/lib/*`
- 真实信息源插件：RSS 轮询、本地 JSON 邮件轮询、钉钉 Webhook 入口
- 真实执行器插件：CLI 执行器、OpenCode CLI 适配器
- 真实规则插件运行时：服务端规则求值与标准动作返回
- 前端插件网关：`src/domain/gateway.ts`
- 信息源页面可触发真实同步
- 任务详情可触发真实执行，并把结果回写任务与运行日志

### 11.2 当前最小接口

**信息源插件**

- `GET /api/plugins`
- `POST /api/sources/:id/sync`
- `POST /api/webhooks/dingtalk/:sourceId`

当前支持：

- `polling` 类型
- 从 RSS 拉取条目
- 从本地 JSON inbox 文件轮询邮件
- 映射成系统事件并写入对应工作空间
- 接收钉钉 webhook JSON 并映射成系统事件

**执行器插件**

- `GET /api/plugins`
- `POST /api/executors/:id/run`

当前支持：

- `cli` 类型
- `opencode` 类型
- 通过本地命令执行
- 读取 JSON/stdout 结果
- 返回 `summary/log/raw`
- OpenCode 命令缺失时 health 返回 `warning`

**规则插件**

- `GET /api/plugins`
- `POST /api/rules/evaluate`

当前支持：

- 本地规则注册表 `data/rules.json`
- `all/any` 条件组合
- `includes/equals` 基础匹配
- 标准动作：`set_level/create_task/assign_executor/archive_event/append_note`

### 11.3 健康检查

- `GET /healthz`
- source 检查启用状态与邮件 inbox 文件可读性
- executor 检查命令是否存在
- OpenCode 缺失只记 `warning`
- rule 检查启停状态

### 11.4 本期实施顺序

1. 先拆 server runtime 模块边界
2. 再补规则运行时与规则注册表
3. 再补 OpenCode / 邮件 / 钉钉适配
4. 最后统一健康检查与 smoke 验证
